## 3. 打开与运行

### 3.1 用 Godot 编辑器

1. 安装 **Godot 4.3 stable**（标准版，非 .NET）。
2. 导入 `game/project.godot`，按 F5 运行。
3. 默认启动场景为 `scenes/boot.tscn`；debug 构建会进入 G2 审核台，release 构建进入正式主线。
4. 首次导入会生成 `game/.godot/` 缓存，属正常现象，不要提交。

### 3.2 直接导出 Windows 包

需要 Godot 4.3 stable 的 Windows 导出模板：

```powershell
# 在仓库根目录
./tools/build.ps1 -BuildId G6-012-local
# 产物：deliverables/G6-012-local/FungusLight.exe + FungusLight.pck
```

> `tools/build.ps1` 与部分 Python 脚本含本机 Godot 绝对路径（`C:/Software/Godot_v4.3-stable_win64.exe/...`）。换机后需按 `README.md` 的“运行与环境”逐项修改并核实。

### 3.3 运行已发布版本

直接解压 `资料包/01-游戏安装包/FungusLight-G6-012-Release.zip`，双击 `Game/开始游戏.cmd`；无需 Godot 编辑器。

## 5. 验证命令

```powershell
# 战斗模型（550 项）
python tools/test_combat.py

# 全套内容/场景/存档/对话/素材/路线（示例编号）
python tools/test_g3_slice.py G6-012-check

# 存档 65 项
python tools/test_save.py G6-012-check

# 路线矩阵（可选，耗时较长）
python tools/test_g4_routes.py

# 发布包审计（构建后；脚本按 deliverables/<BuildId> 读取）
python tools/check_release_package.py G6-012-local
# 五目录布局检查（需先组装到 deliverables/Release）
python tools/check_release_layout.py G6-012-local Release
```

**注意：**

- 不要直接运行 `tools/finalize_g2.py`，它会重写历史报告与门槛。
- 测试输出编号必须显式指定新编号，避免覆盖历史证据。
- 自动化使用 Godot headless/引擎输入注入，不等同于真人键鼠与主观体验验收。
